NETWORK CONNECTIONS DIAGRAM
===========================

========

→ = Data flow
↔ = Shared/component reuse
↓ = Processing/transformation
|| = Concatenation
∑ = Summation/Aggregation
⊖ = Subtraction
⊗ = Element-wise operation

DATA FLOW EXAMPLE (batch_size=1 for simplicity)
==============================================

STEP 1: Get market state
    state = [20, 16]  # numpy array from environment
    state_tensor = [1, 20, 16]  # torch tensor with batch dim

STEP 2: Feature extraction
    features = TemporalFeatureExtractor(state_tensor)
    # features = [1, 256]

STEP 3: Actor forward pass
    action_logits, position_size = Actor(features)
    # action_logits = [1, 17]  (raw scores for each action)
    # position_size = [1, 1]   (value between 0 and 1)

STEP 4: Action selection
    probs = softmax(action_logits)  # [1, 17]
    action_idx = sample(Categorical(probs))  # scalar 0-16
    action_value = action_values[action_idx]  # float from [-0.07,...,0.07]
    pos_size_float = position_size.item()  # float [0,1]

STEP 5: Environment step
    next_state, reward, done, info = env.step(action_value, pos_size_float)

STEP 6: Critic evaluation (for training)
    q_values = Critic(features)  # [1, 17]
    # Q-value for taken action:
    q_taken = q_values[0, action_idx]  # scalar

STEP 7: Learning (simplified)
    # Actor loss: -log(prob) * advantage
    # Critic loss: (q_taken - target)^2
    # Alpha loss: entropy tuning

KEY CONNECTIONS TO REMEMBER
==========================

1. WEIGHT SHARING:
   - Actor and Critic share the TemporalFeatureExtractor backbone
   - This means features learned for action selection also inform value estimation
   - More parameter efficient and encourages coherent representations

2. INFORMATION FLOW:
   Market → Features → (Actor → Actions)  │
                                   ↘      │
                                    Critic → Values
   The Critic evaluates how good the Actor's chosen actions are

3. POSITIONAL ENCODING ROLE:
   - Added BEFORE transformer self-attention
   - Allows transformer to distinguish temporal order
   - Critical for learning patterns like "this indicator combo 5 steps ago means X, but 15 steps ago means Y"

4. DUELING ARCHITECTURE BENEFIT:
   - Separates "How good is this market state?" (V(s))
   - From "How much better is each specific action?" (A(s,a))
   - Especially useful when many actions have similar value (common in ranging markets)

5. N-STEP RETURNS IN TRAINING (not in networks.py but in agent):
   - Target Q = r₀ + γr₁ + γ²r₂ + γ³V(s₃)
   - Reduces variance vs 1-step, reduces bias vs Monte Carlo
   - Implemented via NStepBuffer → PrioritizedReplayBuffer

This architecture enables the agent to learn sophisticated trading strategies that:
- Detect short-term patterns (CNN)
- Understand medium-term trends (BiLSTM)
- Attend to relevant historical regimes (Transformer)
- Make discrete timing decisions (Action Head)
- Manage continuous risk (Size Head)
- Evaluate state-action values accurately (Dueling Critic)
